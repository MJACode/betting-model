**Session summary (2026-09-05, session 229 — college football player props, built and measured before they are scheduled):**

- Matt asked what "an NCAAF prop ingestor" meant — the phrase was mine, from
  #486's report that his approved NCAAF alternates had nothing to ride. Given
  the answer he said *"Yes do it"*.
- **What the gap actually was.** Alternates are extra thresholds on a market
  we already collect; college football had NO player props at all.
  `player_prop_odds` holds 2.82M MLB rows, 157k WNBA, 104k NFL and **zero**
  NCAAF, while the Stats tab has listed college players since the CFBD player
  log landed. Every one of those rows showed a dash where every other sport
  shows a line.
- **Slate size is what makes this different, and it is measured, not
  assumed.** One Saturday (09-05): **120** NCAAF games, **70** with a
  DraftKings game line, **39** FBS vs FBS, **34** priced by our own models.
  A prop pull is one paid call per event, so all 120 would cost more than the
  entire MLB program — and the 50 unlined games are Division III (Lakeland at
  Carthage) with no player props to sell us. `scope_events` keeps only events
  DraftKings has already lined, under `NCAAF_PROP_MAX_EVENTS`. Self-maintaining:
  no hand-kept "big games" list to rot by November.
- **The game id is RESOLVED, never constructed** — the NFL ingestor's lesson,
  and it bites harder here: the feed writes "Ohio State Buckeyes" while CFBD's
  canonical spellings carry accents and punctuation the feed drops ("San José
  State", "Hawai'i"). `resolve_odds_api_school` already solved exactly this for
  game lines, so props reuse it rather than growing a second, differently-wrong
  copy. An event resolving to no known game is SKIPPED: an orphan prop row
  joins to nothing and looks like coverage forever.
- **Nothing is assumed about the feed.** The Odds API uses one key namespace
  for both football leagues and documents neither for college, so the 24
  requested keys are the NFL's under the college sport key; a key it does not
  serve 422s its own chunk (alternates chunked apart from standard markets)
  and the **probe reports which markets, books and players actually came
  back**. That is the number Matt gets before this is scheduled —
  `RUN_NCAAF_PROP_ODDS=0` until then, and the probe is queued as a worker job
  (`ncaaf_prop_odds`, `jobs/declared_jobs.json`) rather than handed over as a
  command.
- **The app half, which is why the board was blank and would have stayed
  blank.** Every sport reaches its prop MARKET through its model id, and
  `rawPropModelForStat` returns null for NCAAF by design (it has four
  game-level models and no prop model), so `propMarketForStat` returned null
  with it — the data alone would have changed nothing on screen. NCAAF now
  resolves through `NCAAF_STAT_TO_MARKET`, a direct stat→market map used only
  for that sport. Twelve of its eighteen board stats get a market; six get
  none because no book prices them, and those columns stay correctly blank.
  `propModelForStat` still returns null, so the board never offers "Add to
  play" on a college row — these lines are research, never a pick.
- **Verified.** `tests/test_ncaaf_prop_odds.py` (14): the DK-line scope, the
  unresolved skip, the resolved id, the per-pass ceiling, the gate being
  optional for a backfill, alternates never sharing a chunk, a rejected chunk
  costing only its own markets, an unrequested book never being written, the
  probe writing NOTHING, the job defaulting to probe and capping its sample,
  and a cross-language check that every market the app's map asks for is one
  the ingestor pulls. Each watched failing under a mutation (gate dropped,
  raw feed names, plain slicing, any book accepted, ceiling removed). Two
  assertions from session 228 said NCAAF had no prop ingest — true when
  written, false now, updated with the reason. Full suite **2,470 passed**.
  tsc: 33 non-cast errors, identical to master, none in touched files.
  `ux_scan` on the four touched files: 11 findings vs 11 on master, **0
  blockers vs 1**. Every verify script passes; `verify_stats_pill`'s one
  failure is the pre-existing BookMark check, byte-identical on master.
- **UX review (frontend-ux-designer, Mobbin connected — six references
  pulled): Ship with fixes, no blockers, five Should-fixes and four
  Considers, ALL TAKEN**, and one of them was a real bug I would have
  shipped:
  - **`def_tackles` was mapped to `player_tackles_assists`, and the two count
    differently.** CFBD charges a shared tackle as a HALF (5 solo + 9 assists
    is stored as 9.5); the book counts solo + assists at FULL credit and would

    about different quantities — §5 of `docs/best_line.md` in its ugliest

  - **`player_anytime_td` was priced honestly but LABELLED as the column.**

    the market also pays on a return TD the board never counted). A bet made
    from that column is now called **Anytime TD** on the pill, the sheet and
    the slip, while the column header keeps its own name
    (`markets.propDisplayLabel`).
  - **Six of the eighteen football columns had no market at all**, and
    `noLinesNote` had no branch for it — the LINE column simply vanished, and
    "no book prices this" looked exactly like "the board is broken". It now
    says so in six words.
  - **The note said "today's games" on a sport whose slate is Saturday from

  - **A one-way market rendered a silent column of dashes**: anytime TD has no

  - Left on record by the review, not taken here: the player-name row wants a

- **The NFL board had the same bug and I extended the fix rather than shipping
  the asymmetry.** `PROP_MARKET_BY_MODEL` carries no `nfl_` entry, so NFL
  resolved its market through a model it does not have — **103,693 NFL prop

  the same blank column. One `FOOTBALL_STAT_TO_MARKET` now serves both; the
  two boards already share column keys by design. Neither league gains an

- **A guard that dead code could satisfy, caught in my own verifier.** One new
  check ended `... && x || y`, which the trailing `||` made true whatever the

  name AND the header still reads the stat — then watched failing under three
  mutations.
- **Not done, on record:** there is still **no NCAAF prop model** — a college
  prop row is research, and a model is its own piece of work on the CFBD
  player log. The ingestor is not on any schedule until the probe's number is
  accepted.

- **What a Stats line becomes: a LINE leg, not a pick** (`lib/lineLegs.ts`).
  The user's own research bet — player, market, the line the board showed,
  the side. No model made it, so it carries no edge and its win probability
  is odds-implied, exactly like a hand-entered custom leg: fair value, never
  a source of edge. It is never written to `picks` and §1c does not apply;
  it re-prices from the latest line every time the slip resolves, because
  the user asked for "the current line", not a locked number. Priced at
  DraftKings when DraftKings posts the line, else at the best bettable book
  that does; `dkPriced` records which, so the betslip's per-book pricing
  does not credit DraftKings with a leg it never posted — the Open-with row
  shows DK at N−1/N and the bet button (`handoffBookFor`) falls through to a
  book that prices every leg, else the one covering most. §6's DK-only rule
  is about what the MODELS decide on; a line leg has no model decision.
- **Persistence:** `hooks/useLineLegs.ts`, a sibling of `useParlaySlip` —
  a pick leg is a stable KEY resolved against today's picks, a line leg has
  no pick to resolve against, so the whole SPEC is stored and re-priced on
  read (`fetchPropLineRows`, one per-game read per leg, plus the game row).
  `useResolvedSlip` resolves both stores: a spec whose read succeeded and
  priced nothing (game started, line pulled) is pruned like a dead pick key;
  a spec whose read failed is held. Line legs follow pick legs in slip order;
  the bar counts both; the betslip removes and clears them through their own
  store.
- **The ask:** `components/AddLineSheet.tsx` — the player, "Over 0.5 Hits",
  the matchup, every bettable book's price for that exact line (best
  starred, DraftKings badged), "Add to betslip" / "Not now", and "Remove from
  betslip" when it is already in. It says in words that the book is chosen
  on the betslip. Reference-only books (ESPN BET, Pinnacle, Bovada) never

**Session summary (2026-09-03, session 207 — the default privileges revoked, and the trap that creates given its own tripwire):**

- mike: *"do the alter default privileges too."*

**Why the sweep alone was not enough.** Revoking the grant on 51 existing tables
fixed the present, not the future: Supabase's default privileges hand
`anon=arwdDxtm` to every NEW table in `public`, so the next one arrives open.
Not hypothetical — `model_artifacts` is created on demand by
`trainer.py::_store_artifact` and came back with the full grant between two
sweeps of the schema hours apart, the same day.

`ALTER DEFAULT PRIVILEGES IN SCHEMA public REVOKE ALL ON TABLES FROM anon,
authenticated`.

**IT CREATES A TRAP, AND THE TRAP IS THE PART WORTH THE CODE.** A new table or
view the app needs now arrives with **no SELECT either**, and that fails
*silently* — PostgREST answers a permission error, the client folds it into
`error`, and the screen renders empty with nothing in any log near the cause.
That is the exact failure shape §7 keeps warning about, and shipping the revoke
without a guard would trade a security hole for a reliability one.

So the read surface is **declared, not inherited**: `data/anon_readable.py` lists
the 33 relations anon may read plus `subscriptions` as authenticated-only, and
`tests/test_anon_readable.py` parses every `.from('...')` in `mobile/src` and
fails if one names something the manifest does not. "Somebody forgot the GRANT"
is now a red test before the PR opens. Asserted in **both** directions — an entry
nothing reads is also a failure, so the list cannot silently accrete.

The manifest matched the app exactly on the first run: **34 relations, none
missing, none stale**. All 34 were already readable, so the grants are a no-op on
today's schema; the mechanism is for what comes next.

**Two limits, measured and stated rather than discovered later.**
`ALTER DEFAULT PRIVILEGES` is **per grantor role**, and `public` tables carry TWO
entries handing anon `arwdDxtm` — one from `postgres`, one from `supabase_admin`.
This changes the `postgres` one, which is the role everything here creates tables
as (worker and pollers over `DATABASE_URL`, and the Supabase SQL editor). The
`supabase_admin` entry needs membership in that role, which `postgres` does not
have on a managed project — latent, not live, since nothing in this repo creates
tables as it.

**Sequences and functions deliberately left alone.** The same defaults grant anon
`rwU` on every new sequence and `EXECUTE` on every new function. The function
half matters — it is how five `SECURITY DEFINER` `feedback_*` RPCs became
anon-callable — but revoking it means every new RPC needs an explicit
`GRANT EXECUTE` or PostgREST 404s it: the same silent-failure surface, needing the
same declared-list-plus-test treatment. `docs/followups.md` carries the shape of
that fix rather than a vague note.

A script rather than a `.sql` file, because the read surface is a Python list a
test cross-checks against `mobile/src`; duplicating it into SQL would let the two
drift, which is the failure this exists to prevent. Same reason
`data.threshold_sync` generates its SQL from `config.py`.

- **THE MECHANISM IS A PYTHON RULE MOST PEOPLE DO NOT KNOW.** `nfl/models/` has
  no `__init__.py`, so it is a **PEP 420 namespace portion**. The platform's
  top-level `models/` HAS one, so it is a **regular package**. When both roots

  save it, and the failure is a hard raise, never a fallback. Both roots are
  always on the path on a scheduled run: `scheduler.py`'s `BASE_ENV` sets
  `PYTHONPATH=<repo root>` so these children can `import monitoring`.

  `monitoring/probe.py`'s writer drops its connection on ANY failure and clears
  its `ensured` flag, so it re-runs the ensure block on reconnect. The busier
  the database got, the more DDL it fired at it, the longer the cache stayed
  down.

  remove redundant work. Uses `%s` placeholders and a cursor fallback so it
